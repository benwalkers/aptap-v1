# ApTap Data Engineer — Release 2

Python/SQLite pipeline for July–September 2026 bank transactions: migrate CSV/JSONL
schemas into reproducible Bronze/Silver/Gold layers, categorise merchants offline,
and report recurring-bill and provider-switch **candidates** with payment evidence.
The supplied sample covers 1,500 synthetic customers. Actual October data is absent.
AWS, Glue/Iceberg and fully bank-contained deployment are **proposed**, not deployed;
Docker execution and Spark/SQLite CDC parity have not been verified.

## Quick start

From this project root (the directory containing `run_all.sh`), use Python **3.11+**.
Python 3.14 was also reported working locally. Keep the supplied July/August CSVs,
September JSONL and `merchant_labels.csv` in [data/](data/).

```bash
bash scripts/workflows/00_setup_venv.sh
bash run_all.sh
```

The setup installs `requirements.txt` for testing, evaluation and reporting; it does
not install MiniLM or Spark. After setup, **`bash run_all.sh` runs the end-to-end
workflow**: source audit, pipeline, categoriser, benchmarks, governance/reports,
tests and same-input rerun verification. This workflow passed in a fresh-state disposable copy during the release-readiness
audit: 54 tests passed and all four CSVs were stable on rerun. See
[execution evidence](docs/RELEASE_READINESS_AUDIT.md).

For just the standard-library pipeline and mandatory commercial report:

```bash
.venv/bin/python -m pipeline data/
```

The core pipeline needs no third-party runtime libraries or inference-time network
calls. A minimal environment can be created using
`bash scripts/workflows/00_setup_venv.sh --offline`; the full workflow still requires
its test/evaluation dependencies. Preserve existing `work/` on reruns. Do not mix
Release 1 SQLite state with Release 2.

Standalone categoriser:

```bash
.venv/bin/python -m categorise examples.csv outputs/examples_categorised.csv --review-output outputs/examples_review.csv
```

It preserves input fields and appends one of the ten scored categories plus
`needs_review`. Uncertain categories are provisional and excluded from trusted
bill/switch evidence; `not_a_bill` is a category, not the review queue.

## Adding October data and safe reruns

Place the supplied `transactions_2026_10.jsonl` beside September in `data/`, then run:

```bash
.venv/bin/python -m pipeline data/
```

Source inspection confirms discovery by source filename period and an automatic
October cutoff of `2026-10-31`, independent of late booking dates. Check `as_of`,
reconciliation, batch actions and runtime/memory in `outputs/run_metrics.json`,
then rerun unchanged and verify the four required CSV hashes remain identical.
`--as-of 2026-10-31` or `AS_OF=2026-10-31 bash run_all.sh` explicitly overrides the
cutoff. The [detailed run guide](RUN_IN_ORDER.md) records a tested synthetic October
procedure, `bash scripts/workflows/07_optional_october_demo.sh`, using separate
`work/demo_october/` state/outputs. **The actual employer October file is untested.**

## Architecture and evidence

Original bytes → content-addressed Bronze → canonical SQLite Silver with
rejected/superseded audit → selective offline classification → trusted-input Gold
bill/switch candidates → reports. Stable bank-scoped transaction IDs distinguish
identical duplicates from valid changed payloads; latest valid observed delivery
wins, with supersession lineage. Without source versions this is an operational
assumption, not proof of source authority. Invalid corrections cannot supersede.
Every occurrence must reconcile: **135,155 = 133,692 active + 1,463 rejected** in
the current sample. See [architecture](docs/ARCHITECTURE.md).

[Release validation](RELEASE_VALIDATION.md) separates current and historical evidence.
The isolated fresh pipeline took **8.842 seconds / 64.4 MiB peak RSS**; its rerun
committed zero new batches and kept all four CSV hashes identical. **54 tests passed**.
The original checkout's metrics remain unchanged and describe an earlier rerun.
See [release-readiness evidence](docs/RELEASE_READINESS_AUDIT.md) and
[test-count reconciliation](docs/TEST_EVIDENCE_RECONCILIATION.md).

Useful validation commands (they may write runtime artefacts):

```bash
bash scripts/workflows/02_run_tests.sh
bash scripts/workflows/06_verify_rerun.sh
bash scripts/workflows/12_audit_merchants.sh
bash scripts/workflows/13_compare_review_scenario.sh
bash scripts/workflows/14_evaluate_pr_curves.sh
```

The 6,681 bills and 209 switches are **candidates**, not confirmed contracts or
cancellations. Observed payment differences do not establish causal or annual
savings. [Bill](docs/BILL_EVIDENCE_VALIDATION.md) and
[switch](docs/SWITCH_EVIDENCE_VALIDATION.md) validators check supporting Silver
transactions, completeness, dates and amounts, not external truth.
The exploratory 57-label lexical benchmark (accuracy 0.789, macro-F1 0.635,
macro-AP 0.698) is not independent production validation. Accepted alias coverage
is not verified accuracy; see [merchant governance](MERCHANT_GOVERNANCE_AUDIT.md).

MiniLM is optional: `bash scripts/workflows/08_optional_install_minilm.sh` provisions
weights online; `bash scripts/workflows/09_optional_run_minilm.sh` uses local weights.
Its similarity is uncalibrated, non-voting diagnostic evidence. See
[deployment](docs/DEPLOYMENT.md) for proposed cloud/bank boundaries and optional
Docker/Spark limitations. PSI and retraining gates are proposals.
